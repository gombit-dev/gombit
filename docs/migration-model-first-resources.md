# Migrating resources to the model-first layout

`gombit make resource` used to emit a **human-owned `handler.go`** (plus
`routes.go`) that you edited to customize a resource. It now emits the
**model-first, generator-owned** layout from [ADR-016](adr/016-model-first-resource-generation.md):
the model is the source of truth, and the request/response DTOs, mappers, and
CRUD handler are regenerated `*.gen.go` files you don't edit. Customization moves
to explicit hooks.

This is a **breaking change** for resources created by the old command. Existing
apps keep compiling — nothing rewrites your files — but a resource still on the
old layout will not be regenerated by `gombit generate` (it fails closed on it),
and re-running `make resource` for it now scaffolds the new shape. Convert each
resource once, at your own pace.

## What changed

| Old (human-owned handler) | New (model-first) |
| --- | --- |
| `internal/<r>/handler.go` — you edited it | `internal/<r>/handler.gen.go` — generated, **do not edit** |
| `internal/<r>/routes.go` — `Register` | `Register` now lives in `handler.gen.go` |
| DTOs hand-written in the handler | `internal/<r>/dto.gen.go` — generated |
| API policy implied by handler code | declared on the model via `gombit:"…"` tags |
| customization by editing the handler | `internal/<r>/hooks.go` (`BeforeCreate`, …) |
| — | `internal/<r>/.gombit-resource` marker |

## Converting a resource

For a resource `internal/book/`:

1. **Move field policy onto the model.** Tag each column in `book.go` with its
   API policy (these replace what the old handler expressed in code):

   ```go
   type Book struct {
       gorm.Model
       Title    string `gorm:"not null" gombit:"read,write,searchable,sortable"`
       TenantID uint   `gorm:"not null" gombit:"read,server"` // set by a hook, not the client
       Secret   string `gombit:"-"`                            // never in the API
   }
   ```

   - `read`/`write` — in the response / accepted on create (untagged columns
     default to read+write).
   - `server` — set server-side in a hook, not from the request.
   - `-` — hidden from the API entirely.
   - `filterable` / `sortable` / `searchable` / `aggregatable` — the list-query
     surface (each requires the field to be readable).

   A field marked `enum(...)` under the old CLI grammar has no model-first
   representation yet; use a plain `string` column for now.

2. **Move handler customization into `hooks.go`.** Anything the old handler did
   between building the row and saving it — setting a tenant/owner id, deriving a
   value — goes in `BeforeCreate`:

   ```go
   func (Hooks) BeforeCreate(ctx context.Context, row *Book, body bookCreateBody) error {
       row.TenantID = tenantFromContext(ctx)
       return nil
   }
   ```

   If you customized more than create (custom list filtering, extra endpoints),
   keep those as your own hand-written file in the package alongside the
   generated handler; they are not regenerated.

3. **Mark the package and delete the old plumbing.** Add the marker and remove
   the human-owned handler/routes so the generated ones can take over:

   ```sh
   touch internal/book/.gombit-resource
   rm internal/book/handler.go internal/book/routes.go
   ```

4. **Generate.**

   ```sh
   gombit generate
   ```

   This writes `dto.gen.go` + `handler.gen.go` and seeds `hooks.go` (if absent).
   Review the diff, wire your customization into `hooks.go`, and commit the
   `*.gen.go` — a per-PR `gombit generate --check` keeps them fresh.

Prefer to start clean? `gombit make resource Book <fields> --force` re-scaffolds
the model and regenerates everything; then re-apply your model edits and hooks.

## Why

Keeping one authoritative representation (model + policy) and deriving the rest
removes the drift that let a new field be rejected on input, silently dropped
from responses, or zero-filled into a NOT NULL column
([#218](https://github.com/gombit-dev/gombit/issues/218)). Regeneration — not
hand-editing several files that must agree — is the synchronization mechanism.
